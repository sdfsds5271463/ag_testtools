二、決定性的數字（2026-09-29 本機實測，deflate + base64url）
====================================================================================================
承載內容                                     原始      壓縮後網址長度   判定
---------------------------------------------------------------------------------------------
tracewager --json 現有 80 個鍵               3.0 KB    ~1,780 字        ✅ 綽綽有餘
  ＋ 120 行時間軸                            14.9 KB   ~2,420 字        ✅ 舒服
  ＋ 12 組原始封包                           18.4 KB   ~2,710 字        ✅ 仍然舒服
純文字報告（一般注單，_test 紀錄實測 49 KB）  49 KB     ~30,000 字       ❌ 貼不進聊天工具
純文字報告（vivid 正常單 454 KB／stage 3 MB） —         —                ❌ 完全不可能

★ 差距 10 倍的原因：
    · CJK 散文 deflate 只壓到 **58~62%**（實測 elk_find/README.md 250 KB → 57.7%）
    · 重複鍵名的 JSON 壓到 **7~15%**（實測 web_map_20260805.json 115 KB → 7.4%）
  工具報告是 CJK 散文，正好落在壓不動的那一邊。

★ 真正的天花板不是瀏覽器（Chrome 位址列到 MB 級；`location.hash` 不經伺服器，
  沒有 Apache/nginx 那條 8 KB request line 限制），而是**分享通道**：
  聊天工具單則訊息多半數千字上限、郵件客戶端會在 78 字折行把網址折斷。
  ⇒ ~2,700 字過得去；~30,000 字連一則訊息都貼不進去。

三、`?` 還是 `#` —— 裁決：**`#`**（初始說明 §2 問的那題）
====================================================================================================
1. 🔴 **fragment 不會送到伺服器。** tracewager／tracelaunch 的輸出**憑證一律原文不遮蔽**
   （tracewager.py 檔頭：2026-08-14 Allen 指示，`elk_base.mask_secrets()` 已 no-op）。
   用 `?` 會把正式環境的 X-API-KEY／userToken／accountToken 送進 GitHub 的存取日誌與 CDN；
   用 `#` 則 GitHub 完全看不到，也會被瀏覽器從 `Referer` 剝掉。
2. 不吃伺服器 URL 長度限制（本機 9527 那支 Apache 鏡像同樣受惠）。
3. base64url 字母表只有 `A-Za-z0-9-_`，**沒有 `&`** ⇒ 繞開 tracelaunch 花大量程式碼在偵測的
   那一族陷阱（shell 在 `&` 截斷、工單把 `&` 轉成 `&amp;`、全形字元）。
4. GitHub Pages 是純靜態，本來就沒有 server-side routing。

建議格式：  https://sdfsds5271463.github.io/ag_testtools/#z1.<base64url>
   `z1.` 是**編碼版本**（不是內容版本），讓頁面能秒判「這不是我認得的格式 → 403」。基底網址 49 字。

★ 壓縮演算法建議 **gzip** 而非 deflate-raw：瀏覽器 `DecompressionStream('gzip')` 支援度較廣
  （Chrome 80+ vs deflate-raw 的 103+），代價只有 18 bytes。
  ⚠️ Python 端務必 `gzip.compress(data, mtime=0)` —— **預設會把當下時間戳寫進去**，
     那會直接踩爆 `ut_determinism.py` 的逐位元組比對。

五、已知會咬人的五個點（實作時逐條處理）
====================================================================================================
1. **tracelaunch.py 目前沒有 `--json`。** tracewager 有（`<<<JSON>>>` 後 80 個鍵）；
   tracelaunch 11 段報告全是文字。這是 Python 側最大的一塊工，**而且它會決定 schema 長相**
   ⇒ 先做它，再回頭讓 tracewager 對齊，不要反過來。

2. 🔴 **「403 不給任何提示」會讓最常見的真實故障變成無法診斷。**
   網址被聊天工具截斷 → 解壓失敗 → 403，跟「沒帶參數」長得一模一樣。
   ⇒ 緩解：**把診斷放在產生端** —— Python 產生網址時跟著印
     「若對方看到 403，多半是網址被截斷，請改貼程式碼區塊」。

3. **欄位靜默消失。** mission_PG 的 `ut_web.py` D 軸抓到過 `vacuum.tables_truncated` 沒人顯示；
   AgWager 的 `OPEN_SECTIONS` 白名單漏註冊 `[1e]` 也發生過 —— 兩次都是
   「不會報錯，只會讓結論變錯」。
   ⇒ 頁面必須有**未分類欄位的 catch-all 區塊**，payload 有而頁面不認得的鍵要原樣攤出來。

4. **JS 快取**（初始說明 §4）：做成**單檔 index.html、JS 全部 inline**，問題直接消失，
   不需要版本號或動態檔名。GitHub Pages 對 HTML 是 max-age=600，10 分鐘可接受。

5. **決定性與 stdout 契約。** 網址是資料 → stdout；耗時等訊息 → stderr
   （tracewager.py 末段已為了 `ut_determinism.py` 踩過這個坑）。
   加上 `mtime=0` 與固定鍵順序 ⇒ 同一份離線樣本跑 4 次必須產出**逐字元相同**的網址。
